# 아파트 월세 흐름 진단과 급변 예측: 9차 보완 연구 설계안

작성 2026-10-05. 같은 날 독립 검토 2회(1차 단일 검토, 2차 수치·구현·방법론 세 관점) 반영. 상태: 초안(설계 동결 전). 8차 확정 계획(docs/연구계획_8차_확정본.md)과 그 실행 보고(docs/연구결과_8차계획_실행보고.md)를 전제로, 전국 단위로 취합이 끝난 국토부 실거래 자료(데이터취합_전처리_20261005.xlsx)를 반영해 무엇을 어떻게 보완할지 적는다. 1장의 자료 점검 수치는 analysis/plan_v9_data_audit.py, 2장의 alpha 표는 analysis/plan_v9_alpha_check.py, 4장의 탐색 수치는 analysis/plan_v9_eda.py 가 다시 계산한다(출력 analysis/output/plan_v9_*.csv, plan_v9_eda_요약.txt).

## 0 요지

- 바뀐 것은 실거래 세 열(V006 월세 건수·전체 건수, V007 매매 건수)뿐이다. 17개 시도에서 결측 94.1% → 0.5%(2차 시트)로 채워졌고 2011.01부터 끊김 없이 있다. 나머지 열은 셀 단위로 같다. 행은 2026.10 한 달이 늘었다.
- 실거래 자료에는 세 가지 함정이 있다. ① 최신 1~2개월은 신고 지연으로 건수가 절단돼 있다(자료 추출 5일 뒤 기준 2026.09 는 전년 동월의 0.41~0.83배, 세종만 1.17; 2026.10 은 0.01~0.05배). ② 2021.06 임대차 신고제로 월세 건수가 한 단계 뛰고 그 폭이 지역마다 다르다(2021년 하반기/2020년 하반기 1.14~2.28배, 전세는 1.05~1.57배). ③ 월세 비중은 2012년 0.18~0.47 에서 2025년 0.38~0.69 로 추세적으로 오른다. ②가 가장 까다롭다. 지역별로 다른 영구 이동이라 월내 편차로도 지워지지 않는다. 그래서 실거래 입력은 모두 로그(또는 로짓) 형태로 두어 곱셈 단절을 지역별 상수로 바꾸고, 경계를 가로지르는 12개월(2차 행 2021.07~2022.06)은 결측, 2022.07 부터는 월별 건수로 추정한 지역별 상수를 빼서 접합한다(1장).
- 탐색 창(결정월 2017.12 이전)에서 실거래 후보의 신호는 약하다. 월내 순위상관(공식 구간 24개월 평균) 은 월세 거래 회전율 0.28, 월세 비중 0.19, 전월세 회전율 0.16, 매매/전월세 비율 0.14 로, 기존 상위 입력(V037 심리 0.61, V032 전세수급 0.46)에 못 미치고 월별 표준편차(0.17~0.32)와 같은 크기다. 채택 근거는 상관이 아니라 ④ 임대시장 동인에 없던 '거래량' 정보라는 사전 논리이며, 기여는 사전 지정 보조 비교(B+실거래 vs B, RQ2·RQ3·결합 예측)로 추정한다. 매매 건수(V007)는 부동산원 매매거래현황(V036)과 |ρ| 0.98 로 같은 정보라 넣지 않는다.
- 변수 간 상관이 높은 것을 빼자는 지적은 절반만 맞다. Ridge 와 RMPI(묶음 안 동일 가중 평균)는 상관이 높아도 예측이 망가지지 않지만, |ρ| ≥ 0.95 인 쌍은 같은 정보를 두 번 세어 묶음 가중을 왜곡하고 기여도 해석(SHAP)을 둘로 쪼갠다. 그래서 중복 군집은 대표 하나만 남기고(R2), 공통 블록에서는 시간 추세와 구분되지 않는 입력을 뺀다(R1). 목표와의 상관이 약하다는 이유로는 빼지 않는다(R3). 탐색 창이 24~61개월뿐이라 그 선택 자체가 과적합이 된다.
- 8차 결과가 남긴 과제는 진단을 바로잡아 반영한다. 고정 alpha 10 은 h=1 에서는 너무 크고(A·B 모두 alpha 0.01 에서 MAE 가 21%·21% 낮아져 B 는 mom1 을 이김), h=6 에서는 B 에 거의 최적이고 A 에는 너무 작다(2장 표). 8차의 1-SE 재튜닝 민감도는 교차검증 최소점보다 큰 alpha 만 고르므로 이 사실을 보여 주지 못했다. 9차는 전국 Ridge(RQ1)의 alpha 를 수업자료 절차대로 전진 교차검증 평균 손실 최소로 고르고, 패널(RQ2·RQ3)은 8차 고정값을 주 사양으로 두고 같은 튜닝을 민감도로만 돌린다.
- 8차 결과를 보고 바꾸는 항목(RQ1 alpha 선택, h=1 해석 규칙, 윈저라이즈, 확장 실험 삭제, XGBoost 부록)은 모두 사후 결정이고 2·3·5·7장에 그렇게 표기한다. 평가 구간(2018.01~2025.12)은 유지하되 9차 판정은 '설계 동결 후 역사적 재검증(2차)' 으로 표기한다.

실거래 네 입력의 월내 순위상관은 모두 월별 표준편차보다 작거나 비슷하고, 12개월합이라 월 사이가 겹쳐 유효 표본은 24개월보다 적다. 채택은 R3 와 사전 논리(임대 거래량과 구조가 ④ 동인에 없었음)에 따른 것이고, 효과는 보조 비교로 추정한다. 전세 건수는 전체 = 전세 + 월세의 항등식이라 사용자 표기(2_데이터목록 'X')대로 쓰지 않는다(로짓 비중의 분모로만 쓴다). 서울 25개 구 시트에도 같은 열이 2011년부터 있으므로 구 보조 분석(7단계)에도 같은 네 입력을 넣는다.

## 5 9차 설정 파일에서 바꿀 항목 (config/plan_v9_settings.yaml, 8차 대비)

1. inputs: 데이터취합_전처리_20261005.xlsx / 데이터취합_20261005.xlsx. posthoc_label_end 2026-09. data_asof 2026-10(실거래 '최신 2개월' 규칙의 기준).
2. variables 추가(지역 블록 전용): RT_share(logit 월세 비중, level_and_d12, ④ 전환구조, ±), RT_rent(log 월세 회전율, flow_per_1000hh_log, ④ 거래, ±), RT_all(log 전월세 회전율, flow_per_1000hh_log, ④ 거래, ±), RT_saleratio(log 매매/전월세, level_and_d12, ③ 매매수급거래, ±). 원열 매핑(rt_columns: 월세·전세·전체·매매)을 설정에 두고 data.transform 이 파생을 계산한다. 지금 코드는 derived_from 을 CSI 에만 특수 처리하고, 원열이 없으면 조용히 건너뛰므로(transform 의 `continue`) 파생 변수 처리와 '원열 없음 → 오류' 를 넣는다. check_settings 의 '열 ↔ 변수 대응' 점검에 CSI 와 같은 예외를 추가한다.
3. excluded_columns: V006 월세·전체 건, V007 매매 건을 뺀다(파생에만 쓰고 직접 입력하지 않음). V006 전세 건은 로짓 분모로만 쓴다. 삭제하는 V009·V044 의 원열은 excluded_columns 에 넣어 대응 점검을 통과시킨다.
4. 출력 단위 공통 블록 포함 여부(in_common) 필드 신설: V009·V044 변수 삭제. V011a 로그Δ12, V003·V004·V011c·V072 의 수준, V005 수준, V015 수준, V017 수준, RT_* 전체 → in_common false. 나머지 지역 변수 출력은 true. 코드에서 공통 블록 열을 고르는 다섯 곳(engine.national_run·panel_run, models.features, data.decompose) 이 이 필드를 보도록 고친다. blocks 와 common_exclude 두 가지 방식 대신 이 하나로 한다.
5. masking 추가: rt_break_first_row 2021-07(RT 네 입력의 모든 형태 12행 결측, 기대 결측 셀 수를 check_settings 에 추가), rt_splice_from 2022-07(지역별 접합 상수: 월별 로그 건수의 월내 편차 평균 차, 분해 뒤 D 에서 뺌, data.build 의 decompose 와 price_trend 사이에 단계 추가), rt_truncate_last_months 2(data_asof 기준, 사후 확인·전향 운용 전용). robustness_extra_lag 는 원열(V006·V007)을 밀도록 lag_adjust 를 고친다(지금은 변수 col 만 밀어 파생 입력에는 효과가 없음).
6. rmpi: winsor_sd 5(표준화 뒤). sign_rule: 4.1 의 규칙(± 는 두 블록 모두 Spearman, 사전 부호 입력은 지역 = 사전, 공통 = Spearman 우선 |ρ| ≥ 0.1·n ≥ 8). index._sign_of 에 블록·사전 부호·최소 |ρ| 인수 추가, 1월 재학습마다 부호 기록.
7. models: ridge_national 의 alpha 를 nested(2장: 2단계 격자 29점, ForwardMonthSplit 검증 12개월, 평균 손실 최소, 평평하면 10 에 가까운 것, 격자 끝이면 한 번 연장, 매년 1월 재선택, 폴드 < 4 이면 10)로 — 주 사양(사후 결정). ridge_panel 170·logistic_panel C 1/170 은 주 사양 유지, 같은 nested 를 민감도로(C 는 Brier 손실, 단일 계급 폴드 제외). 고정 10·1-SE 는 전국 민감도. 확장 실험(대용계열) 삭제. 부록 모형: XGBoost(h=6, 전국 B 와 패널 급락, 2단계 탐색 Stage 1 n_iter 20 → Stage 2 격자 9) 만. 기준 오프셋은 쓰지 않는다(1차 검토본의 제안을 철회: 패널에는 선택형 단순기준이 정의돼 있지 않고, 절편 때문에 alpha → ∞ 극한이 단순기준이 아니며, 2장 표가 보여 주듯 축소 강도 조정으로 충분).
8. naive·events·inference·timing(평가 2018.01~2025.12) 유지. 보고서 표기: '설계 동결 후 역사적 재검증(2차)'. 보조 비교 B+실거래 vs B 를 RQ2·RQ3·결합 예측에 추가(RQ1 은 실거래가 공통 블록에 없어 같은 모형). 판정이 아니라 추정으로 사전 지정: d̄, 두 t구간, MAE(Brier) 비율, 연도별 우세 수를 보고하고, 최소 유의 효과 δ = 평가 지표의 2% 를 미리 정해 '두 구간 상한 < 0 이면 기여, 두 구간 하한 > −δ 이면 기여 없음(동등), 그 외 불확실' 로 읽는다. 8차 RQ2 의 연평균 구간 반폭은 MAE 의 약 2~6% 였으므로 검출 가능 효과도 그 수준임을 미리 적는다. 7단계 동인 제거에서 실거래 묶음을 빼는 절제(ablation)를 함께 보고한다.

## 6 실행 단계와 예상 비용

8차의 7단계 그대로 돌린다. 1단계(설정 동결·점검) → 2단계(자료 진단: 실거래 열 추가, 절단·단절·접합 기록) → 3단계(흐름 진단: 월세 비중·회전율 그림 1장 추가) → 4단계(지수 구축: R1·R2 적용 뒤 구성명세, 상관 중복표 재계산) → 5단계(파이프라인 점검: 과거 절단 불변 항목에 튜닝·선별·접합 상수 포함) → 6단계(예측 평가) → 7단계(해석: 동인 제거에 실거래 묶음 추가, XGBoost 부록, 서울 구 보조).

8차 실행 당시 세션 기록(보고서에는 없음)으로 6단계 45분, 7단계 26분이었다. 9차는 전국 중첩 튜닝(1월마다 29점 × 최대 12폴드 × 정보군 2 × h 3 = 2,000여 회의 작은 Ridge 적합, 몇 분)과 패널 튜닝 민감도(로지스틱 C 탐색이 대부분, 약 30분)를 더해 6단계 약 1.5시간, 7단계 약 40분으로 본다(XGBoost 부록 제외 시 7단계 30분).

## 7 결정이 필요한 항목

1. 평가 구간: 2018.01~2025.12 유지(권고). 2020 년 이후로 줄이면 결정월 72개로 판정 검정력이 더 떨어진다. 대신 9차 판정은 '역사적 재검증(2차)' 로 표기한다.
2. 전국 Ridge 의 alpha 교차검증 최소 선택을 주 사양으로(권고, 사후 결정임을 표기). 패널은 8차 고정값 유지, 튜닝은 민감도.
3. 공통 블록 추세 입력 제외(R1)·중복 대표(R2)·공통 블록 부호의 자료 결정: 적용(권고). R2 로 공통 블록에서 빠지는 것은 V009, V011a, V044, V005 수준, V015 수준, V017 수준 이다. V005(월세수급)를 공통 블록에 남기고 싶다면 V032 대신 V005 를 대표로 바꿀 수 있으나 관측이 2015.08 부터라 권고하지 않는다.
4. 실거래 입력의 로그·로짓 형태, 2021.07~2022.06 결측, 2022.07 부터 지역별 접합: 적용(권고). '실거래 수준형 제외' 는 민감도.
5. 매매 건수는 V036 유지, V007 은 쓰지 않음(권고). V007 을 쓰려면 V036 을 빼야 한다.
6. XGBoost 부록(약 10~15분 추가): 포함(권고, 수업자료 모형과의 대응).

위 6개가 정해지면 config/plan_v9_settings.yaml 과 analysis/check_settings.py 를 고쳐 1단계로 동결하고, 그 뒤 2~7단계를 돌린다.
